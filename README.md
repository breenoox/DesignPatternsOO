<h1 align="left">Design Patterns O.O</h1>

###

<p align="left">Este projeto foi desenvolvido com o objetivo de praticar e consolidar o uso de alguns **padrões de projeto (Design Patterns)**, organizados conforme suas categorias clássicas:<br><br>
### 🔹 **Padrões Criacionais**<br>- **Singleton**<br>- **Factory Method**<br><br>
### 🔹 **Padrões Estruturais**<br>- **Adapter**<br>- **Decorator**<br><br>
### 🔹 **Padrões Comportamentais**<br>- **Chain of Responsibility**<br>- **Strategy**</p>

###

<h2 align="left">Padrões Criacionais</h2>

###

<p align="left">`Singleton:` Garante que uma classe tenha apenas uma única instância durante toda a execução do sistema, oferecendo um ponto de acesso global a esse objeto.<br><br>`Factory Method:` Centraliza e abstrai a criação de objetos, desacoplando a lógica de criação do uso, o que facilita a manutenção e a extensão do sistema.</p>

###

<h2 align="left">Padrões Estruturais</h2>

###

<p align="left">`Adapter:` Permite integrar bibliotecas ou sistemas externos sem alterar o núcleo do projeto. Caso a implementação mude no futuro, basta trocar o adaptador, mantendo o restante do código intacto.<br><br>`Decorator:` Permite adicionar novos comportamentos a um objeto de forma dinâmica, sem modificar sua classe original. Ajuda a seguir o princípio Open/Closed, permitindo extensão sem alteração do código existente</p>

###

<h2 align="left">Padrões Comportamentais</h2>

###

<p align="left">`Chain of Responsibility:` Permite que uma requisição passe por uma cadeia de objetos, onde cada um decide se pode tratá-la ou repassá-la para o próximo. Assim, quem envia a requisição não precisa saber quem irá processá-la.<br><br>`Strategy:` Permite definir diferentes algoritmos para um mesmo comportamento e trocá-los facilmente em tempo de execução, sem alterar o código do cliente que os utiliza.</p>
